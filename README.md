# XAI-iBPM: Explainable AI for Intelligent Business Process Management

Code and result files for the paper **"Explainable AI for Intelligent Business Process Management: Integrating
Predictive Decisioning, Process Mining, and Human-Centric Governance"** (XAI-iBPM).

XAI-iBPM is a framework for outcome-oriented predictive process monitoring that makes automated process decisions
accountable. It stacks Bayesian-tuned LightGBM, XGBoost and CatBoost models and a causal Transformer with a
logistic meta-learner and a monotone post-hoc calibrator. It explains the stack with exact ensemble TreeSHAP and
compares it with LIME (stability, agreement, deletion fidelity). Its governance layer combines Mondrian (class-conditional)
conformal deferral to human analysts with a transparent cost rule ("intervene if q > c/b"). The framework is evaluated
against seven baselines (LR, RF, XGBoost, LightGBM, CatBoost, LSTM, Transformer) on ten outcome-prediction tasks from
four public event logs (BPIC2012, BPIC2017, Sepsis, Traffic Fines). It uses two protocols: BENCHMARK, which reproduces
the preprocessing of Teinemaa et al. (2019), and STRICT, a leakage-free protocol. The evaluation uses five seeds,
Friedman/Nemenyi and Wilcoxon–Holm tests, and case-level bootstrap.

## Environment

- Python 3.13 (the experiments used Python 3.13.18 on Linux x86-64), CPU only; no GPU is needed.
- Install the pinned dependencies:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

`torch==2.15.0` installs the default wheel for your platform. A CPU-only wheel is sufficient
(`pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu`).

All commands below are run from the repository root. Directories can be redirected with the environment variables
`XAI_IBPM_PARSED`, `XAI_IBPM_WORK`, `XAI_IBPM_RESULTS` and `XAI_IBPM_FIGURES` (see `src/config.py`).

## Preprocessing (both protocols)

```bash
bash scripts/02_prepare.sh
# equivalent to, for each group:
#   python3 src/prepare.py benchmark {bpic2012,bpic2017,sepsis_cases_1,sepsis_cases_2,sepsis_cases_3,traffic_fines_1}
#   python3 src/prepare.py strict    {bpic2012_accepted,bpic2017_accepted,sepsis_cases_1,traffic_fines_1}
```

- **BENCHMARK** (10 tasks) re-implements the labelling and preprocessing of the benchmark of Teinemaa et al. (2019)
  ([irhete/predictive-monitoring-benchmark](https://github.com/irhete/predictive-monitoring-benchmark)). BPIC traces are
  not truncated. The inter-case feature `open_cases` is included. The three BPIC tasks of a log share one encoding.
  The prefix cap K is min(40, q90 of positive case length), or min(20, ·) for BPIC2017, and 10 for Traffic.
  Traffic cases that end with "Send Fine" are removed.
- **STRICT** (4 tasks, one per log) cuts every trace before the first outcome-revealing event. It drops
  `open_cases` and the BPIC2017 offer attributes `Selected`, `Accepted` and `CreditScore`, which encode the later
  outcome. K = 20 (Traffic 10).
- Both protocols use a temporal 80/20 train/test split by case start, with events of training cases after the split
  time removed. They split train 80/20 into fit/validation in the same way. Validation is halved by case start into
  part A (meta-learner and calibrator) and part B (conformal calibration and deferral thresholds).

Outputs go to `work/<protocol>/<group>/`: `X.npz`, `meta_*.parquet`, `seq.pkl` and `info.json`.

## Full pipeline

```bash
bash scripts/run_all.sh              # = 01_parse_logs, 02_prepare, 03_train, 04_evaluate_explain, 05_aggregate
JOBS=3 bash scripts/03_train.sh      # individual steps; JOBS = concurrent single-threaded processes (default 3)
```

A full run writes intermediate files to `work/` (about 2 GB) and results to `outputs/results/`, which has the same
layout as `results/`, so the shipped results are not overwritten. Set `XAI_IBPM_RESULTS=results` to write in place.

## Reproducing the tables and figures

**From the shipped result files (no data, no training, about 20 s):**

```bash
bash scripts/rebuild_from_results.sh
```

This script re-runs `aggregate.py` (all `ALL_*.csv` files and the Friedman/Nemenyi/Wilcoxon–Holm statistics) on
`results/per_task/` and `results/run_metadata/`. It then runs `build_summary.py`, `figures.py` and `make_tables.py`.
The regenerated `ALL_*.csv` files are identical to the shipped ones, and the numbers in all generated tables match the
paper.

**From scratch:** `bash scripts/run_all.sh`. The final step (`05_aggregate.sh`) runs the same scripts on

## Runtime, hardware and seeds

- **Hardware of the original run:** 2 vCPU, 7 GB RAM, no GPU (Linux x86-64, Python 3.13.18). Every model used
  one thread (`n_jobs`/`thread_count` = 1, `torch.set_num_threads(1)`), and up to three processes ran concurrently.
- **Wall-clock:** about **2 h** for the whole pipeline (preprocessing, tuning, training, evaluation, XAI and
  figures). Per-task process times are in `results/ALL_runtime.csv` and `results/runtime_env.md`. They sum to about
  3.9 h of single-thread process time: 2.6 h tree-model tuning and training, 0.9 h deep models and 0.4 h evaluation.
  The longest task is BENCHMARK BPIC17-ref, at 41 min of tree-model tuning. Preprocessing takes under 1 min in
  total, and the XAI step takes under 1.5 min per task. Parsing the XES files takes a few minutes.
- **Seeds:** training seeds 0–4 for all stochastic models (RF, GBMs, LSTM, Transformer, stack); LR is deterministic.
  The Optuna TPE sampler uses seed 0. Case subsampling uses seed 0 for fit and seed 1 for validation. The bootstrap
  uses seed 0 for AUC CIs and pairwise tests and seed 1 for prefix-length bands. XAI sampling uses seed 0. All seeds
  are fixed in the code (`common.SEEDS` and the scripts); no option changes them.

## Known deviations and caveats

1. **Training cap of 80,000 prefixes.** Because of compute limits, the fit split is subsampled by whole case to at
   most 80,000 prefixes (`FIT_CAP`, seed 0). Validation is capped at 50,000 (`VAL_CAP`, seed 1) and Optuna trials at
   30,000 fit prefixes (`TUNE_CAP`), all in `src/common.py`. This affects BPIC2017, where about 20% of prefixes are
   used, and Traffic (25–28%). Test sets are never subsampled.
2. **8-minute tuning cap.** A wall-clock cap of 480 s per model-family Optuna study was added for the four tasks
   tuned last: BENCHMARK BPIC17-can and Traffic, and STRICT BPIC17-acc and Traffic. It cut XGBoost to 6 trials
   (BENCHMARK BPIC17-can) and 16 trials (STRICT BPIC17-acc). All other studies completed their full budget of
   30/30/20 trials (LightGBM/XGBoost/CatBoost). `scripts/03_train.sh` reproduces this by passing `TUNE_TIMEOUT=480`
   to those four tasks and `TUNE_TIMEOUT=inf` to the rest. Because the cap counts wall-clock time, the number of
   completed trials, and thus the selected hyper-parameters, can differ on other hardware. The trials completed in
   the paper run are in `results/ALL_best_params.csv` (`n_trials_completed`) and `results/ALL_optuna_trials.csv`.
3. **Order of the evaluation and XAI runs.** After the XAI step, `evaluate.py` was re-run for all tasks to make the
   calibrator choice monotone (non-decreasing Platt/beta, otherwise identity). The XAI outputs in
   `results/per_task/*/*/{shap_*,xai_*,waterfall_*}` were computed with the stack weights of the earlier evaluation.
   The meta-learner weights did not change, except on BENCHMARK BPIC12-acc (largest absolute weight difference
   0.0012). A fresh run of `run_all.sh`, which runs evaluation before XAI, can therefore differ slightly in the SHAP
   numbers for that task. The weights used for each explanation are recorded in `per_task/*/*/xai_info.json`.
4. **STRICT BPIC2017** was first run with the benchmark feature set. That run exposed the leakage through
   `Selected`/`Accepted`/`CreditScore` and was discarded. Only the corrected run is reported, and the code here
   contains the correction (`AggEncoder` in `src/prepare.py`).
5. **Library versions.** `results/runtime_env.md` records pandas 3.0.5 at experiment time. The environment this
   repository was packaged in, from which `requirements.txt` was pinned, has pandas 2.3.3. For the closest
   replication, install `pandas==3.0.5`. All other pinned versions match the run.
6. **Bit-exact replication is not guaranteed.** All seeds are fixed and every model runs on one thread. We re-ran
   BENCHMARK Sepsis-2 end to end from the parsed log in the packaging environment (pandas 2.3.3, 4 min). The
   encoded data, XGBoost-default, LR and the deep models were reproduced exactly or to within 0.002 AUC. The
   LightGBM and CatBoost default-configuration validation AUCs differed slightly from the original run (for example
   0.9488 vs 0.9514). Through Optuna, this changed the selected hyper-parameters, so per-seed test AUCs of the tuned
   models and the stack differed by up to 0.04 on this small task (157 test cases). Expect results within seed-level
   noise rather than identical numbers. Use the shipped `results/` to check the paper's tables exactly.
7. Sepsis-3 is the benchmark's "Release A" task, which the benchmark scripts write to `sepsis_cases_4.csv`.
   Sepsis-1 is anti-predictive under the temporal split and serves as a negative control (see the paper).
